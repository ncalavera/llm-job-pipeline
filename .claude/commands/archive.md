# /archive

Помогает почистить дашборд от мусора, который скоринг оценил низко, но
автоархив не тронул (или скоринг ошибся в обе стороны).

## Шаги

1. Загрузить из Supabase все вакансии со `status = 'unseen'` и
   `llm_score IS NOT NULL`.
2. Сгруппировать по brackets'ам: 0-10, 10-20, 20-30, 30-40.
3. Показать сводку:
   ```
   0-10:   42 вакансии — junk (engineering, sales)
   10-20:  18 вакансий — borderline, blind-scored: 5
   20-30:  11 вакансий — низкий fit, обычно мусор
   30-40:   7 вакансий — пограничные
   ```
4. Для каждой группы спросить: архивировать всё / показать список и
   выбрать / пропустить.
5. Если "показать список":
   - Печатать по одной: title, org, score, location, первая строка
     reasoning.
   - Подсветить `blind-scored` теги — у них скор менее надёжный.
   - Спросить: `liked` / `passed` / `skip` / `quit`.
6. По итогам сессии — обновить статусы в БД массово через
   `update_vacancy_statuses({uuid: 'passed', ...})`.
7. **Никогда не архивировать без явного подтверждения.** Покажите
   точный список того, что собираетесь поменять, и попросите `y/n`.

## Восстановление

Если архивировали лишнее — это просто `status = 'passed'`, ничего не
удалилось. Восстановить:

```bash
python3 scripts/vac.py mark <id> --status unseen
```

Или массово через SQL:

```sql
UPDATE vacancy SET status = 'unseen', status_updated_at = NOW()
WHERE id IN ('<uuid1>', '<uuid2>', ...);
```

## Когда запускать

- После каждого `/score` — посмотреть, что осело в нижних brackets.
- Раз в неделю — почистить накопившееся.
- Перед `/triage` — чтобы liked-список был чистым.
