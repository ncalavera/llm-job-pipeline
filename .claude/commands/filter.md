# /filter

Quality gate. Запускает `scripts/filter_vacancies.py` и интерпретирует
результат.

## Шаги

1. Спросить:
   - Включить fuzzy-дедупликацию между источниками (`--dedup`)?
   - Dry-run (`--dry-run`) — посмотреть что бы удалил, без изменений?
2. Запустить:
   ```bash
   python3 scripts/filter_vacancies.py [флаги]
   ```
3. Прочитать вывод — там пять групп:
   - `delete_blacklist` — попали в `GLOBAL_BLACKLIST` по заголовку.
   - `delete_usa` — попали в `LOCATION_BLACKLIST`.
   - `delete_stale_blind` — старые «слепые» вакансии без описания.
   - `reenrich_blind` / `reenrich_thin` — нужны повторное обогащение.
   - `ready` — готовы к скорингу.
4. Если в blacklist улетело >20% от общего — показать топ-10 удалённых
   заголовков. Возможно, в фильтре ошибка.
5. Если есть `reenrich_blind` — предложить запустить
   `python3 scripts/enrich_blind_vacancies.py` для повторного обогащения
   через Firecrawl.

## Если фильтр глотает что-то важное

Каждая запись `delete_blacklist` содержит причину — какой паттерн
сработал. Если паттерн ложно-положительный (например, «Operations
Engineer» отфильтрован из-за `engineer`):

1. Откройте `scripts/config.py`.
2. Найдите паттерн в `GLOBAL_BLACKLIST`.
3. Замените на более узкое выражение (например, `software engineer`,
   `senior engineer` вместо просто `engineer`).
4. Прогоните `/filter` ещё раз.

## Если что-то пропускает

Если в `ready`-список регулярно попадают вакансии, которые вы потом
ставите в `passed` — добавьте паттерн в `GLOBAL_BLACKLIST`. Команда
покажет частые мусорные слова в верхней части отчёта.
