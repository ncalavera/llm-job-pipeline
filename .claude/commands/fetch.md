# /fetch

Запускает `scripts/fetch_vacancies.py` с правильными флагами после
короткого диалога.

## Шаги

1. Прочитать `scripts/config.py` — посмотреть, какие job boards и ATS
   стратегии подключены.
2. Спросить пользователя (один вопрос за раз):
   - Что собирать: все источники / только компании / только boards /
     выбранные компании.
   - Игнорировать TTL (`--force-all`) или соблюдать (по умолчанию 3-7
     дней между фетчами одного источника).
   - Включить Firecrawl-enrichment описаний вакансий (если есть
     `FIRECRAWL_API_KEY`).
   - Сразу прогнать filter+score после сбора (`--auto-score`)?
3. Запустить:
   ```bash
   source ~/.zshrc 2>/dev/null
   python3 scripts/fetch_vacancies.py [флаги по выбору]
   ```
4. После завершения показать сводку: сколько новых вакансий, сколько
   ошибок по источникам.
5. Если были ошибки сбора — предложить запустить `python3
   scripts/discover_ats.py --unsourced` для повторного определения ATS.

## Флаги fetch_vacancies.py

| Флаг | Что делает |
| --- | --- |
| `--force-all` | Игнорировать TTL, тянуть все компании |
| `--companies "A,B,C"` | Только перечисленные канонические имена |
| `--tier S` | Только компании с тиром S |
| `--no-boards` | Пропустить job boards |
| `--auto-score` | После сбора прогнать filter + score |
| `--auto-score-limit N` | Сколько вакансий скорить (по умолчанию 50) |
| `--report-only` | Только перегенерировать `public/data.js` без сбора |

## После сбора

Если новых вакансий мало или 0 — это нормально. TTL по умолчанию 3-7
дней. Если хочется срочно — используйте `--force-all` или
`--companies "Имя1,Имя2"`.

Если у компании растёт `fetch_error` — её страница careers, скорее
всего, поменяла структуру. Запустите `/add-source` повторно для этой
компании, чтобы переопределить ATS.
